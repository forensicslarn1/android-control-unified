De-Google integration / 08

De-Google becomes migration planning

08

01 / INVENTORY

Start with the device that exists

Candidate package counts are based on the connected device inventory, not a generic static total.

  • Installed-package review
  • Level-specific preview
  • Visible package names
No assumed packages

02 / GUARD

Apply OEM-aware caution

Manufacturer profiles highlight vendor-sensitive components and retain core services as review-only.

  • Manual profile selection
  • Auto-detected context
  • Expert-review indicators
No core bulk action

03 / REPLACE

Prepare alternatives first

Alternatives show category, source, direct user-initiated link, and Android-version compatibility.

  • Search and filters
  • Compatibility badges
  • Local Favorites control
No auto-download

04 / RECORD

Export the migration shortlist

Saved Favorites become a timestamped local case bundle with readable and structured records.

  • Manifest and case ID
  • Markdown and JSON
  • Local user export
No silent install

MIGRATION RULE

Prepare compatible replacements before changing a dependency. The De-Google workflow is a documented transition plan: review the real device, choose a cautious reversible action where appropriate, and retain the alternatives record locally.
