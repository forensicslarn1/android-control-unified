## Cover

# Authorized Forensics + De-Google

### A safe, local workflow for Android assessment, evidence records, and migration planning

## Slide 1

# One local operating model

- Evidence Snapshot documents selected device facts.
- De-Google reviews reversible package actions and compatible alternatives.
- Serial assessment adds non-destructive interface observation.

## Slide 2

# Serial assessment starts with authorization

- Operator declares device, interface, and case scope before any connection.
- Port inventory is reviewed without automatic enumeration or opening.
- The default mode observes only data already received.

## Slide 3

# No arbitrary serial transmission

- No exploit delivery, shell injection, debugging enablement, or auto-approval.
- Unknown and write-capable strings are not accepted by the UI.
- A future active-probe mode would require a reviewed, read-only allowlist and per-command receipts.

## Slide 4

# Evidence status remains intelligible

- Every operation is labeled success, blocked, failed, skipped, or paused.
- UTC timestamps, tool state, configuration, and case reference remain with the record.
- A blocked request is preserved as evidence rather than bypassed.

## Slide 5

# Screenshots need a capture record

- Capture begins from a deliberate mirror-frame action.
- Previewed redactions stay separate from the original image.
- Image, local hash, note, timestamp, and receipt ID export together.

## Slide 6

# Packet evidence is import-first

- The browser app does not claim raw packet capture on non-rooted Android devices.
- Authorized PCAP or diagnostic artifacts can be imported with metadata and local hashes.
- Original capture inclusion requires an explicit privacy acknowledgement.

## Slide 7

# De-Google becomes migration planning

- Device inventory and OEM guards determine the reviewable package set.
- Alternatives display compatibility, source links, search, filters, and Favorites.
- Migration Favorites export as a timestamped local case bundle.

## Slide 8

# One case bundle joins the records

- `case-manifest.json` carries case reference, chosen scope, device context, and timestamps.
- Separate evidence, migration, screenshot, and supplied packet records remain reviewable.
- Browser-local export remains user initiated and can adopt encryption.

## Slide 9

# Next safe implementation sequence

- Add UI-only serial assessment and local findings record.
- Add screenshot evidence export with hash and redaction preview.
- Add packet evidence import, case consent, and optional encrypted export.
